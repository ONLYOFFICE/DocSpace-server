# webhooks-and-api-keys — verification

Every requirement and scenario of `spec.md`, with where it was verified. Paths are relative to the repo root
(`server/`); test paths omit the `web/ASC.Web.Api.Tests/Tests/` prefix unless another project is named, and
`unit/` stands for `common/Tests/ASC.Core.Common.Tests/Webhooks/`. `yaml` is
`sdk/docspace-api-spec/docspace-backend.yaml`, `contract` is `sdk/docspace-api-spec/webhooks/docspace-webhooks.yaml`
(identical to the embedded copy `common/ASC.Webhooks.Core/Contract/docspace-webhooks.yaml`). Status:
**TEST-CONFIRMED** (an integration or unit test asserts it), **CODE-ONLY** (read from the product code, the
OpenAPI document or the contract, no test), **NOTES-ONLY** (only the release notes say it — nothing of that kind
was written into the spec; such items are listed at the end as left out).

Revised 2026-11-04 after the merge of release/v4.1.0 (`3533ad8a89`, previous state `d58816bece`). The release
rewrote the webhook delivery (`web/ASC.Web.Studio/WebHooks/WebhookSender.cs`, `Services/WorkerService.cs`,
`common/ASC.Webhooks.Core/DbWorker.cs`, `WebhookPublisher.cs`), introduced typed payload models
(`common/ASC.Api.Core/Webhook/Payloads/*WebhookDto.cs`, `products/ASC.Files/Core/ApiModels/WebhookDto/*.cs`), the
generated contract (`common/Tools/ASC.Webhooks.Contract`, `.claude/skills/generate-webhook-sdk/SKILL.md`), the
`[RaisesWebhook]` attribute on API actions, and the delivery test suites that run a WireMock.Net receiver in
the test process (`02_Settings/Webhooks/WebhookReceiver.cs`, `WebhookDeliveryTestBase.cs`, the `IsSignedWith`
helper). The legacy `common/Tests/ASC.Webhooks.Tests` project was deleted. The delivery suites write to the
MySQL of the integration-test profile for states no API call produces (`ExecuteSqlAsync`); the profile retries
3 times, 500 ms apart, with a 12 s request timeout (`common/ASC.AppHost/Configuration/Constants.cs`
`WebhookTestRetryCount`, `WebhookTestRetryInterval`, `WebhookTestRequestTimeout`), and narrows the blacklist's
loopback range to `127.0.0.1/32` so that the receiver on `127.0.0.2:18089` is reachable (`WebhookTestBlacklist`,
checked against the default by `WebhookTestProfileTests`).

## Left out of the spec, and why

- **Developer Tools page, JavaScript SDK samples, OAuth2 applications** (v1.1, v3.0, v3.5, v3.7, v4.0): client
  pages and the OAuth2 service (`ASC.Identity`) are outside this capability; OAuth2 is not covered by the Web.Api
  test suites read here.
- **`WebhookDisable` attribute** (`common/ASC.Api.Core/Core/WebhookDisableAttribute.cs`): marks controllers whose
  actions must not themselves be reported as webhook events; the publishing is explicit through the managers, so
  nothing observable to specify.
- **The property lists of the payload schemas** (`UserPayload`, `FilePayload`, …): the contract is the normative
  list and is kept equal to the code by `WebhookContractTests`; the spec names the families, the per-subscriber
  cuts and the fields the tests assert, not every property.
- **The webhook SDKs themselves** (the `webhooks/` folder of each SDK submodule, the generator templates and
  `gen-trigger-map.py` under `common/Tools/ASC.Webhooks.Contract/Sdk/`): generated artefacts of the contract;
  their generation and verification is the `generate-webhook-sdk` skill.
- **The `WebhookTrigger` bit values above 2^30** are given as powers of two because the OpenAPI document and the
  SDK carry them as `long` values; no test asserts them.
- **`ssl=false` with an `https` target**: the HEAD probe and the delivery then skip certificate validation
  (`PinnedHttpClientSslIgnore`, `WebhookHttpClientSslIgnore`); mentioned in the URL-validation requirement, no
  test. The `https` half of "SSL left out follows the scheme" needs a public https host and is untested.
- **Thread count of the sender** (`webhooks:threadCount`, default 10, cut to 100), the claim lease (10 minutes
  or the attempt lease), the upkeep period (10 minutes) and the sender's poll period (5 seconds): operational.
- **Row bookkeeping of a backup restore or a region move** (`RestoredFromBackupNote`, `MovedInFlightNote`):
  the backup capability.
- **TS scenario "API key with accounts:read scope cannot access rooms"**: not ported (the Web.Api test project
  has no Files client); the route map in the spec is CODE-ONLY for the rooms rows.
- **`lastModified` of the setter's echo**: the tests note it carries the default timestamp on this host; not
  specified.
- **Audit-trail entries** (`WebhookCreated/Updated/Deleted/Retried`, `ApiKeyCreated/Updated/Deleted`,
  `DevToolsAccessSettingsChanged`) are named in the requirements but their content belongs to the audit-trail
  capability.
- **`form.submit` delivery**: not captured and not driven by any suite — it is published from the Document Server
  save callback (`WebhookFixtureCaptureTests` remarks); `Fixtures/form.submit.json` is hand-written.

# backup-and-restore — verification

Every requirement and scenario of `spec.md`, with where it was verified. Paths are relative to the repo
root (`server/`). `yaml` is `sdk/docspace-api-spec/docspace-backend.yaml`; `BackupController` is
`common/services/ASC.Data.Backup/Api/BackupController.cs`, `BackupService` is
`common/ASC.Data.Backup.Core/Service/BackupService.cs`, `BackupProgressItem` / `RestoreProgressItem` are in
`common/ASC.Data.Backup.Core/Service/ProgressItems/`, `BackupRepository` is
`common/ASC.Data.Backup.Core/Storage/BackupRepository.cs`, the worker services in
`common/services/ASC.Data.Backup.Worker/Services/`. `Tests/` alone means
`common/Tests/ASC.Data.Backup.Tests/Tests/`. Status: **TEST-CONFIRMED** (a test asserts it), **CODE-ONLY**
(read from the product code or the OpenAPI document, no test), **NOTES-ONLY** (only the release notes say it).
Exception → status mapping used throughout: `SecurityException` 403, `ArgumentException` 400,
`BillingException` / `TenantQuotaException` / `AccountingPaymentRequiredException` 402, `ItemNotFoundException` /
`FileNotFoundException` / `DirectoryNotFoundException` 404, `NotSupportedException` 415, any other exception 500
(`CustomExceptionHandler` in `common/ASC.Api.Core/Middleware/ResponseWrapper.cs:53-114`, registered by
`common/ASC.Api.Core/Core/BaseStartup.cs:129`).

Revised after the merge of `hotfix/v4.0.1` (`183da52625`, previous state `34df477e4e`). That range added the
integration suite `common/Tests/ASC.Data.Backup.Tests` (74 test files; `ASC.Tests.slnx`, and the backup service plus
its worker in the `integration-test` profile of `common/ASC.AppHost/Program.cs:86-89`) and fixed bugs 84509, 84510,
84511, 84512, 84513 and 80605, the archive naming of back-to-back backups and the concurrency of `deleteBackup`.

What the suite can and cannot show: it runs on the Aspire `integration-test` profile, which is a **standalone**
installation (`APP_HOSTING_STANDALONE=true` in `common/ASC.AppHost/Properties/launchSettings.json`), so the free
allowance, the 402 refusals, the paid service and the `restore` tariff feature are never exercised; those rows stay
CODE-ONLY. The restore itself is never started: every restore request goes through `Tests/Restore/RestoreGuard.cs`,
an allow-list that throws before sending anything whose `backupId` could be a GUID or whose `storageParams` could
carry a `filePath` (`RestoreGuard.cs:37-53`; the guard's own tests are `RestoreGuard*Tests.cs`). The Nextcloud and S3
cases skip without `NEXTCLOUD_*` / `S3_*` in the environment (`Tests/Start/StartBackupToExternalStorageTests.cs:59-61,
91-94`). A test name can disagree with its assertion; the rows below cite the assertion.

## Left out of the spec, and why

- **Wallet, prices, top-up, enabling the service through the wallet settings, transaction history**
  (`04_Portal/Payments/*`, `PaymentsController.SetTenantWalletSettings`): out of scope; only "is the
  backup allowed" is used.
- **Portal transfer between regions** (`TransferProgressItem`, `StartTransferAsync`, the migration
  letters): a hosted-only operation without an API endpoint in this document.
- **Server-wide dump internals** (`DoDump`, `mysql` upgrade scripts, `RestoreFromDump`, license reset
  after a dump restore): the dump is covered only as the `dump` parameter and the space-access rule.
- **Backup worker sizing** (`backup.json`: `Limit` 100000 rows per select, 4 backup workers, 1
  scheduler worker, 7-day temp-file cleaner): configuration, not behaviour.
- **Audit event names and letter texts** beyond the ones named (`BackupStarted`, `ScheduledBackupStarted`,
  `BackupCompleted`, `RestoreStarted`, `CustomerOperationPerformed`): see `history-and-audit`.
- **Which plan carries which feature** (Startup 0 / Business 2 free backups, `restore` on Business): catalogue
  data of the hosted offering, stated only as what the notes say.
- **`DistributedTaskStatus` numeric values, `BackupStorageType` numbers**: enum numbers are kept out of the
  spec by convention; the yaml lists them. The tests send `storageType` 99 and -1 and `period` 3 and -1 as
  "outside the known values".
- **The test-side restore guard** (`RestoreGuard.cs`, `RestoreGuardData.cs`, `RestoreGuard*Tests.cs`): test
  infrastructure that keeps the suite from restoring the standalone test database; it asserts nothing about the
  server beyond the observation recorded under B3.
- **The 415 for a typed null body**: the generated client sends no content type for a null body and the
  framework answers 415 before the action (`Tests/Schedule/CreateBackupScheduleValidationTests.cs:56-59`); the
  tests send such bodies raw with a JSON content type instead, which is the 400 the spec states.
